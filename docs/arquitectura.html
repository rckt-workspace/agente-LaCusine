LA CUISINE APPLIANCES · ARQUITECTURA v1.1 · 27 OCT 2026

Agente comercial WhatsApp + Claude + Supabase

Arquitectura objetivo para leads de campañas, recomendaciones fundamentadas, registro de conversaciones y transferencia a asesores. El MCP oficial de Meta se utiliza para configurar y probar recursos; no es el motor de respuestas de producción.

Proceso de venta conversacional

Del clic en el anuncio al asesor comercial, manteniendo límites claros.

01 · Adquisición

El cliente inicia conversación desde anuncio. Registrar fuente solo si Meta entrega el metadato.

02 · Calificación

Preguntar categoría, marca/modelo, ciudad y presupuesto de forma progresiva y con minimización de datos.

03 · Recomendación

Consultar catálogo aprobado, compartir enlaces y advertir que los precios son de referencia.

04 · Detección de intención

Interés alto, cotización, instalación, garantías o casos no soportados generan escalamiento.

05 · Intervención humana

Pausar automatización cuando interviene un asesor; nunca prometer una transferencia automatizada no implementada.

06 · Métricas

Volumen, tiempo de respuesta, leads calificados, escalaciones y costo por conversación.

Roadmap de implementación

FASE 0 · HOY

Repo y seguridad

Privatizar repositorio público; no subir datos internos, secretos, números ni mensajes reales.

FASE 1 · LOCAL · COMPLETADA

Webhooks simulados

FastAPI con handshake, validación de firmas y tests. Sin llamar a Meta ni Claude.

FASE 2 · DATOS · IMPLEMENTADA

Supabase

Esquema SQL, RLS, tablas de leads, mensajes y eventos. No almacenar más de lo necesario.

FASE 3 · IA · IMPLEMENTADA (sin llamadas reales)

Claude

Prompts comerciales basados en conocimiento autorizado, presupuesto máximo y límites de tokens.

FASE 4 · WORKER · IMPLEMENTADA (sin envío)

Worker y cola

Cola PostgreSQL con leases, orden por contacto, reintentos, presupuesto con reservas y outbox. Las respuestas quedan pendientes de envío.

FASE 5 · META · IMPLEMENTADA (envío desactivado)

Integración WhatsApp

Adaptador Cloud API y dispatcher probados con transporte simulado. Envío real desactivado. Requiere autorización para activarse.

FASE 6 · PRODUCCIÓN · PENDIENTE (requiere autorización)

Salida a producción

Preparación de Render lista, sin desplegar. Proyecto Supabase real, diagnóstico de la cuenta de WhatsApp y piloto autorizado.

Costos: Claude API (tokens), Meta (según tipo de mensaje/mercado), hosting y Supabase (cuotas/uso), anuncios aparte. El MCP de Meta no reemplaza el runtime productivo.

Motor comercial de IA

Estado real de cada componente. Nada de esta sección envía mensajes ni llama a Claude en el entorno actual.

IMPLEMENTADO Y PROBADO

Orquestador comercial

Orden fijo de controles: apagado, control humano, datos sensibles, idempotencia, escalamiento determinista, presupuesto y validación. 40 conversaciones simuladas.

Repositorio de productos

Búsqueda parametrizada con límite de 5 resultados, filtro de presupuesto, referencia exacta y corrección de erratas contra el catálogo real.

Contexto conversacional

Hasta 8 mensajes y 3000 caracteres, solo de la conversación actual. Se reconstruye desde PostgreSQL tras un reinicio.

Calificación

Etapas NEW, DISCOVERY, QUALIFIED, HIGH_INTENT, HUMAN_REQUIRED y CLOSED a partir de señales observables, no de puntuaciones del modelo.

Control de costos

Estimación con tarifas configuradas y reservas persistentes antes de cada llamada, con límites diario, mensual y por interacción. Son estimaciones, no facturas.

Seguridad de salida

Rechaza JSON inválido, descuentos, stock garantizado, fechas exactas, pagos confirmados, asesoría jurídica definitiva y enlaces fuera del dominio oficial.

IMPLEMENTADO Y PROBADO

Adquisición atómica

SELECT ... FOR UPDATE SKIP LOCKED en transacción corta. Dos workers nunca reclaman el mismo evento (prueba con dos conexiones simultáneas).

Lease y token de propiedad

Solo el worker dueño del token puede finalizar. Un lease vencido se recupera; un worker antiguo queda rechazado (prueba de integración).

Orden por contacto

Solo se procesa el evento más antiguo de cada contacto y línea de negocio, con exclusión persistente en contact_leases.

Reintentos y revisión manual

Backoff exponencial con jitter para errores transitorios; error permanente a dead_letter; resultado incierto a manual_review sin reenvío.

Presupuesto con reservas

Reserva persistente antes de cada llamada facturable, bajo bloqueo de transacción. Prueba con 8 hilos: nunca se supera el límite diario.

Outbox transaccional

Respuesta generada y estado comercial en una transacción. Una respuesta por evento. Estado pending: generada, no enviada.

Transferencia humana

Escalamiento idempotente con motivo y prioridad; bloqueo de respuestas automáticas mientras un asesor controla la conversación.

Retención segura

Solo se eliminan estados finales. Pendientes, en proceso y en revisión se conservan.

IMPLEMENTADO Y PROBADO LOCALMENTE

Adaptador Cloud API

POST a Graph API con versión configurable. Errores tipados con resultado explícito: no enviado, o incierto. Sin reintento sobre resultados inciertos.

Envío desactivado por defecto

Dos interruptores (META_SEND_ENABLED y WHATSAPP_DRY_RUN) y lista de destinatarios autorizados. Configuración inválida falla cerrada.

Dispatcher del outbox

Reclamo con lease y orden por conversación. Cancela si un asesor tiene el control y bloquea fuera de la ventana de 24 horas.

Estados de Meta

sent, delivered y read llegan por webhook y solo avanzan. Un estado que llega antes que el envío se reintenta, nunca se pierde.

Seguridad del webhook

Firma HMAC, límites de tamaño y estados persistidos como eventos separados, sin contacto.

Flujo extremo a extremo simulado

Webhook firmado → worker → IA simulada → outbox → envío simulado → estado entregado, con duplicados sin efecto.
